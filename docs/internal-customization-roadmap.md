# GEOFlow 内部改造路线图

## 目标

当前阶段不对接外部工作台，先把 GEOFlow 改造成一套稳定、简单、围绕“每日生产内容并分发”的内部生产系统：

1. 每天按计划生成主文章并自动发布到 WordPress。
2. 从同一篇主文章生成百家号、腾讯新闻、网易号、搜狐号、头条号、知乎和微信公众号版本。
3. WordPress 支持自动发布；其他平台先支持生成、审核、导出、复制和人工发布回填，后续再按平台能力逐步自动化。
4. 日常操作集中到生产看板、任务、文章、渠道和基础素材，降低维护成本。
5. 保持上游代码可同步：优先使用配置开关、独立服务和新增表，不直接删除上游模块或修改已执行迁移。

## 当前能力盘点

| 模块 | 当前能力 | 分类 | 第一阶段处理 |
|---|---|---|---|
| 仪表盘 | 展示素材、任务、文章、审核、分发、访问和 AI 指标 | 改造 | 改为“今日生产、待审核、待发布、失败任务、渠道状态”运营看板 |
| 素材中心 | 栏目、作者、关键词库、标题库、图片库、知识库 | 保留 | 保留核心入口，减少重复卡片和高级入口 |
| 任务中心 | 定时扫描、生成任务、状态控制、任务运行记录 | 改造 | 增加每日计划、主文章与平台稿生成策略、明确下一次执行时间 |
| 文章中心 | 草稿、审核、风险扫描、发布、回收站、微信 HTML 导出 | 改造 | 增加“内容组”视图：一篇主文章及其所有平台版本 |
| 分发中心 | WordPress、通用 HTTP、GEOFlow Agent、重试与日志 | 改造 | 日常入口优先 WordPress；平台稿进入独立发布队列 |
| AI 配置 | 模型、正文提示词、关键词和摘要提示词 | 保留 | 增加平台改写模板分组和可测试预览 |
| 站点设置 | 站点、首页模块、主题、广告、敏感词 | 保留 | 默认只展示站点基础配置和内容安全，高级设计能力折叠 |
| 数据分析 | 访问、内容、渠道、线索等综合统计 | 隐藏 | 首期从主导航隐藏，保留路由和数据 |
| 线索与表单 | 前台表单、线索收集、处理与导出 | 隐藏 | 当前内容生产目标不依赖，保留代码和表结构 |
| 企业知识工程 | 文件生成企业知识草稿、版本和发布知识库 | 隐藏 | 保留普通知识库，先隐藏复杂的企业知识工作流 |
| URL 导入 | 抓取网页、解析、预览并写入素材 | 隐藏 | 作为高级工具保留，不放在日常导航 |
| 主题复制 | AI 分析参考站、生成主题、预览与打包 | 隐藏 | 与当前文章生产无关，保留超级管理员入口但默认隐藏 |
| 系统更新中心 | 检查、备份、应用和回滚更新 | 隐藏 | 保留运维入口，避免日常误操作；代码更新走 Git 分支流程 |
| API Token | API v1 访问令牌 | 隐藏 | 工作台对接暂停期间，仅超级管理员通过高级设置访问 |
| 管理员与审计 | 管理员、权限、操作日志 | 保留 | 放入系统设置，不占用主导航 |

## 不直接删除的模块

首轮不物理删除数据表、路由、控制器和服务。以下功能只从默认导航和首页快捷入口隐藏：

- 数据分析与线索中心
- 企业知识工程
- URL 导入
- 主题复制
- 系统更新中心
- API Token 管理
- GEOFlow Agent 站点包与前端能力同步入口

原因是这些模块与上游耦合较深，直接删除会显著增加合并冲突，也会让已有数据库迁移难以回退。待内部流程稳定并连续运行一个版本周期后，再决定是否真正移除。

## 必须改造的业务链路

### 1. 内容生产计划

将“任务”明确分成四层配置：

- 主题来源：关键词库、标题库、知识库和人工选题。
- 主文章策略：文章结构、长度、语气、SEO、配图和 WordPress 栏目。
- 平台改写策略：每个平台独立的标题、长度、口吻、结构、标签和结尾规则。
- 发布策略：生成时间、审核方式、WordPress 发布时间和其他平台计划时间。

### 2. 内容组

一个选题形成一个内容组：

```text
主文章
├── WordPress 版本
├── 百家号版本
├── 腾讯新闻版本
├── 网易号版本
├── 搜狐号版本
├── 头条号版本
├── 知乎版本
└── 微信公众号版本
```

平台稿必须保留与主文章的关联、改写版本、审核状态和发布状态，不能覆盖主文章正文。

### 3. 发布工作台

发布工作台需要统一呈现：

- 待生成
- 生成中
- 待审核
- 待发布
- 发布中
- 已发布
- 失败待处理

WordPress 通过现有 REST 发布能力自动完成。没有稳定官方接口的平台，首期提供正文复制、封面下载、标签建议、平台格式预览和“标记已发布/填写链接”。

### 4. 失败恢复

- 主文章生成失败与平台改写失败分别重试。
- 单个平台失败不能阻塞其他平台稿。
- 外部发布任务需要明确失败回调、指数退避和最终失败状态。
- 所有人工重试必须幂等，避免 WordPress 重复发文。

## 后台简化方案

默认主导航调整为：

1. 生产看板
2. 生产计划
3. 内容中心
4. 发布中心
5. 素材中心
6. AI 配置
7. 系统设置

高级功能统一放入“系统设置 > 高级功能”，并通过配置控制是否显示。隐藏只影响导航，不改变路由权限；敏感操作仍保持超级管理员、密码确认、CSRF 和限流保护。

## 实施批次

### 批次 A：后台简化

- 增加内部生产模式配置。
- 重组主导航和仪表盘快捷入口。
- 隐藏非核心模块，但保留可恢复入口。
- 为导航与权限增加功能测试。

### 批次 B：内容组与平台模板

- 新增内容组和平台版本数据模型。
- 新增八个平台的模板配置。
- 支持从主文章批量生成平台稿。
- 增加平台稿审核和版本历史。

### 批次 C：发布队列

- WordPress 自动发布接入内容组。
- 其他平台增加人工发布包和状态回填。
- 完善分发失败回调、重试、幂等和日志。

### 批次 D：运营看板

- 今日计划与完成率。
- 待审核、待发布、失败任务。
- 按平台统计发布量和失败率。
- WordPress 发布结果与文章链接。

## 暂缓范围

- 与外部工作台的 API 对接。
- 百家号、腾讯、网易、搜狐、头条、知乎、微信公众号的非官方登录自动化。
- 删除上游模块、历史迁移或数据库表。
- 大规模重做前台主题系统。

## 验收标准

- 日常使用者不需要进入高级功能即可完成每日内容生产。
- 一个每日任务可以生成一篇主文章及八个平台版本。
- WordPress 自动发布可追踪、可重试且不会重复发布。
- 其他平台稿可以审核、导出、复制并回填发布链接。
- 任一平台失败不会影响其他平台。
- 上游更新可以通过 `upstream/main` 合并到定制分支，核心定制保持独立且冲突可控。
